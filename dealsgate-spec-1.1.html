§9.2.AVet Agent Training Programme

FINAL 1.0 §9.2 specified a read-only module sequence with a quiz. This section locks the exact structure.

  • Module 01 · Role & Conduct — core duties, ethics, zero-affiliation rule
  • Module 02 · Inspection Protocol — pre-arrival, on-site, verdicts
  • Module 03 · Evidence Upload — photos, continuous video, content hashing
  • Module 04 · Smartphones — IMEI, battery health, account lock checks
  • Module 05 · Laptops — serial, power-on, ports, battery
  • Module 06 · Cameras & Drones — serial, lens, gimbal, propellers
  • Module 07 · Vehicles — VIN vs papers, odometer, engine
  • Module 08 · Bags & Watches — stitching, serials, hallmarks
  • Module 09 · Other Sectors — appliances, solar, B2B bulk counts
  • Module 10 · Scam Detection — top 10 Nigerian scam patterns
Certification gate: 10 modules complete + quiz ≥ 85% pass mark. Quiz bank: 100 questions, 25 randomly drawn per attempt, 30-minute time limit. Badges: Certified Eligible (post-quiz) → Certified (3 successful inspections) → Super Vet (10 at 4.5★+).
§18.APolicy Library — Full Enumeration

FINAL 1.0 §4.1 and §18 listed 4 required policies. The production policy library contains 11 documents, all drafted to NDPA 2023 standards.

  • 01 · Terms of Service
  • 02 · Privacy Policy — NDPA 2023 aligned
  • 03 · Refund & Cancellation Policy — maps §13 branches
  • 04 · Dispute Resolution Policy — evidence-tier weighting
  • 05 · Acceptable Use Policy
  • 06 · Prohibited Items List — 9 categories
  • 07 · Data Retention & Security Policy
  • 08 · Complaints & Escalation Policy — FCCPC aligned

Mandatory consent set: at signup, users must accept Terms of Service, Privacy Policy, and Refund & Dispute Policy. Acceptable Use is optional. Acceptance is persisted with policy_key, policy_version, accepted_at, IP, and user agent.

§23.7Byzantine Agent Threat Model

FINAL 1.0 §23 listed validation, authorization, webhook verification, idempotency, signed URLs, and 2FA. It did not name the largest single technical risk in the system. This section adds it.

The risk. The evidence gate assumes that continuous video and IMEI-on-camera evidence capture the actual physical item at the actual inspection location. If an agent's device is rooted or jailbroken, or the app itself is modified, the agent can inject pre-recorded footage or spoof GPS position. The buyer then approves a report that does not correspond to the item they will receive.

Why it matters. The evidence gate is the structural invariant the entire protocol rests on. If a single compromised device can break it, the platform's security reduces to the weakest mobile client — and DealsGate becomes a standard escrow service with extra steps.

Mitigation path
  • Hardware-backed device attestation. Mobile capture client signs each frame with a device-bound key (Android Keystore / iOS Secure Enclave). Server rejects any unverifiable signature.
  • Motion co-capture. Accelerometer and gyroscope readings captured with each frame. Injected footage will not match the device's motion profile.
  • Monotonic server timestamps. Each frame carries a server-issued timestamp. Pre-recorded footage cannot be replayed against a later timestamp.
  • Structured red-team exercise. Quarterly adversarial testing — one team attempts frame injection on a rooted device, one attempts GPS spoofing via mock location providers. Every successful bypass is patched and re-tested.
  • Fallback controls. If attestation can be bypassed, escalate to dual-device signing (seller and agent cross-verify) and mandatory buyer unboxing video stored as Tier-2 evidence.
Status: Attestation layer is scheduled for the production build. It requires the mobile capture client, which requires the engineering team that funding enables. The MVP artifacts demonstrate the flow but do not carry cryptographic attestation.

§24.ADelivery Model — Web-First PWA

FINAL 1.0 §24 said "mobile-first." FINAL 1.1 locks the delivery decision precisely: DealsGate ships as a progressive web app.

  • Web-first PWA. Runs on any modern mobile browser. Installable to the home screen. No app store review cycle, no forced updates, no per-platform builds.
  • Reduced surface area. One codebase, one deployment, one security perimeter. Critical at the PoC-to-MVP stage.
  • Single-link access. Reviewers, investors, and early users open the product from a URL — no install required. This is why the 13 MVP artifacts already run in a browser.
  • Native capture client deferred. A dedicated mobile capture app for Vet Agents is planned for the production build, driven by the hardware-attestation requirement in §23.7. The web PWA remains the primary buyer and seller surface.
Confirmed stack: Next.js + React + TypeScript · Node.js / NestJS · PostgreSQL · Redis · S3-compatible object storage · Paystack / Flutterwave behind a PaymentService abstraction · GIG / Kwik behind a LogisticsService abstraction.
